# XP curve multiplier (optional, via Mod Configuration Menu)

Added 2026-10-08. One build for everyone: with [MCM](https://www.nexusmods.com/baldursgate3/mods/9162) installed the player
gets an "XP gain multiplier" slider (0.25 to 2.0, default 1.0) under Path to Apotheosis > Experience; without MCM nothing
changes. 1.0 is the shipped curve (`XPData.txt`), tuned to reach level 20 by the end of the game.

## Files
- `Mods/<folder>/MCM_blueprint.json` - the setting. `"Optional": true` so MCM doesn't warn that it is a missing dependency.
- `ScriptExtender/Lua/XPCurve.lua` - reads the value, scales XP gains of party members. Not registered at 1.0 or without MCM.
- `ScriptExtender/Lua/XPTable.lua` - GENERATED by `Scripts/gen_xp_table.py` (in `regen_all.sh`) from `XPData.txt`.

## Why it scales gains and not the table
`XPData` isn't reachable from the Script Extender (`Ext.Stats`: "Unknown stats entry type: XPData"). The per-character
`Experience` component is, and `Ext.Entity.Subscribe("Experience", ...)` reports every change.

## How the engine tracks levels (verified 2026-10-08)
- A level is earned when the total reaches the cumulative threshold (level 11 starts at 58,500). At that moment the engine sets
  `AvailableLevel` (the earned level) and `CanLevelUp`, and resets `CurrentLevelExperience` to 0.
- It only checks when XP is *added*. Lowering the total afterwards (negative `AddExplorationExperience`, or writing
  `TotalExperience`) leaves a level the full gain crossed flagged. Resetting `AvailableLevel` by hand without fixing
  `CurrentLevelExperience` strands the character (58,600 XP, no level-up).
- Above 1: the extra XP is added with `AddExplorationExperience`; the engine does the level maths.
- Below 1: the surplus is subtracted the same way, then (3 ticks later) `reconcile` rebuilds the state from the scaled total:
  `AvailableLevel`, `CurrentLevelExperience = total - START[level]`, and `CanLevelUp` removed or created (`RemoveComponent` /
  `CreateComponent`). Never below the level the character already has.
- Only gains are scaled; losses pass through. Changing the setting affects future gains only.

## MCM facts
- MCM injects the global `MCM` into mods that load AFTER it. If PTA loads first (Vortex put MCM last), `MCM` is nil and MCM logs
  "uses MCM but is loaded before MCM itself". XPCurve falls back to `Mods.BG3MCM.Get{settingId=, modUUID=}` (untested, see below).
- `MCM.Set` doesn't fire `MCM_Setting_Saved` unless `shouldEmitEvent = true`; the in-game UI does. The value is persisted either way
  and is read at SessionLoaded.
- `Ext.Require` inside an event callback has no mod context: require files at load time. Osiris DBs can't be read at SessionLoaded:
  use entity components (`PartyMember`).

## Verified in game 2026-10-08 (Tavizard save, MCM 1.41.0)
| case | result |
|---|---|
| 0.5x, +19,000 from 48,500 (raw would cross level 11) | total 58,000, earned level 10, no level-up |
| 0.5x, +1,000 landing exactly on 58,500 | earned level 11, level-up through the UI OK |
| 0.5x, +30,000 (raw would reach level 13) | total 73,500, earned level 12, progress 4,500, level-up OK |
| 1.5x, +2,300 | +3,450 |
| 1.5x, +400 crossing level 13 only after scaling | earned level 13 |
| back to 1.0 | subscription removed, +1,000 unscaled |
| MCM not installed | no errors, gains unscaled |

Not verified: the `Mods.BG3MCM.Get` fallback when MCM loads after PTA, multi-character parties, other mods that change
XP (UnlockLevelCurve, XP Curve Adjustment Patch: they replace `XPData`, which makes `XPTable.lua` wrong).
